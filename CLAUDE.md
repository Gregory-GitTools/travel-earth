# Travel Earth — контекст для Claude

Это новый проект, выделенный из [travel-globe](https://github.com/Gregory-GitTools/travel-globe) 2026-09-26 после обсуждения архитектуры глобуса. Ничего ещё не реализовано — этот файл фиксирует принятое решение и техническое видение, чтобы новый чат мог продолжить без повторного обсуждения с нуля.

## Проблема, которая привела к этому проекту

В travel-globe используются два разных движка: globe.gl/three.js для 3D-глобуса и Leaflet для плоской карты, с явным "прыжком" (dive) между ними при зуме. У этой связки два минуса:
1. Совместимость двух режимов вызывает постоянное трение (разные системы координат, разные попапы, разные системы стилизации) — уже отдельная тема в travel-globe.
2. На глобусе при приближении к конкретному участку границы материков теряют чёткость — глобус использует одну статичную растровую текстуру на весь шар, а не тайлы с уровнями детализации.

Решили не чинить это патчами поверх текущего стека, а сделать новый проект на другом движке.

## Принятое архитектурное решение

Единый движок — **MapLibre GL JS** с `projection: 'globe'`. Это open-source (форк Mapbox GL) тайловый рендерер, который умеет рисовать сферу и плавно, без дискретного переключения, зумиться от вида из космоса до уровня улицы — то есть тот самый "прыжок глобус→карта" из travel-globe исчезает как отдельная сущность, потому что это один непрерывный движок с одной системой координат.

Слои, которые предполагается добавить поверх базового тайлового глобуса (в этом порядке приоритета не зафиксированы, обсуждались все три):
- **Спутниковый слой** — растровые тайлы (например, Esri World Imagery, бесплатно без ключа) как альтернатива обычной карте, с обязательной атрибуцией (стандартный маленький текст в углу, как сейчас в Leaflet-версии travel-globe).
- **Языковые подписи** — отдельный векторный слой подписей поверх тайлов, рендерящийся из данных с языковыми тегами (OSM хранит `name`, `name:en`, `name:ru` и т.п. на каждом объекте). Это даёт возможность переключать язык подписей как параметр стиля — то, что было недоступно в travel-globe (там названия зафиксированы языком исходных тайлов). Провайдеры со стилями, поддерживающими выбор языка: MapTiler, CARTO.
- **Геопривязанные истории/объекты** — свой собственный GeoJSON/vector source с точками (путешествия, фото, заметки), рисуемый тем же способом, что и упомянутые выше слои — то есть данные травел-блога (см. ниже) становятся ещё одним слоем на этом движке, а не отдельным приложением.

При переносе логики пинов на MapLibre GL эти грабли неактуальны (MapLibre не использует CSS2DRenderer), но полезно знать, какие проблемы уже решались в похожей задаче.

## Статус

Первый прототип готов: `index.html` + `app.js` — MapLibre GL 5 (с unpkg), `projection: 'globe'`, переключатель карт внизу слева по образцу Google Maps (`#basemap-switcher`, массив `BASEMAPS` в app.js): большая плитка показывает «другой» вид (на карте — Спутник, на спутнике — последнюю карту) и переключает одним кликом, при наведении раскрывается ряд всех вариантов (2026-09-30, Грегори: «всё в уровень с иконкой карт, минимальная рамка, без подпрыгивания»): панель в высоту большой плитки (76 px), белая рамка 2 px, плитки 72 px с подписью поверх снимка, рамка выбора — `::after` поверх снимка, размер не меняется. Шесть бесплатных вариантов без ключа: Спутник (растровые тайлы Esri World Imagery, без подписей), Пастельная = CARTO Voyager (по умолчанию), Яркая = OpenFreeMap Liberty, Контрастная = OpenFreeMap Bright, Светлая = CARTO Positron, Тёмная = CARTO Dark Matter. Выбор сохраняется в localStorage. Миниатюры `icons/basemaps/<id>.jpg` снимает `node tools/basemap-thumbnails.mjs` (при запущенном start.bat) — перезапускать при добавлении/смене стиля. Свечение атмосферы (`setSky`) пробовали и убрали: Грегори оно показалось просто засветкой. Стили OpenFreeMap показывают подписи на двух языках (латиница + местное написание) — пригодится для слоя языков подписей. Непрерывный зум от глобуса до улиц проверен. Данных о поездках пока нет. Следующий шаг — по одному пункту из списка слоёв выше; порядок слоёв ещё не выбран.

Интерфейс по образцу Google Maps (сделано 2026-09-27):
- **Раскладка (2026-09-27, по просьбе Грегори, одинаковая для компьютера и телефона):** вверху поиск (на узком экране сжимается), язык и справа кнопка «Места» (`#places-btn`): она показывает и прячет столбик категорий под собой, сверху вниз, «Магазины ▾» последними. Кнопка серая, пока столбик открыт или включён фильтр (`updatePlacesBtn`); белая — только если столбик свёрнут и фильтров нет (цветную точку Грегори счёл неоднозначной). Внизу справа в одну строку (`.bottom-row`, собирается в app.js): шкала, ⓘ, шестерёнка; кнопки масштаба над ними. Раскрытая строка ⓘ ложится поверх шкалы, шкала не двигается.
- **Вверху слева** — поиск (Nominatim, только по Enter/кнопке: правила Nominatim запрещают автодополнение; результаты рядом с видимой областью идут первыми через `viewbox` + `bounded=0`), кнопка языка подписей и чипы категорий.
- **Язык подписей** (`LANGUAGES`, `applyLabelLanguage` в app.js): все векторные стили — схема OpenMapTiles с тегами `name:xx` (~80 языков), поэтому у каждого symbol-слоя, чей `text-field` упоминает `name`, подменяется `text-field` на `coalesce(name:xx, name)`. Есть «Без подписей» (прячет эти слои) и «Местные названия» (`name`). По умолчанию русский. Выбор в localStorage.
- **Спутник** — растр Esri + поверх него из векторных тайлов OpenFreeMap: границы, крупные дороги, названия мест/вод/улиц белым с тёмной обводкой (`buildSatelliteStyle`). Язык и «Без подписей» работают и на нём.
- **Чипы категорий** (Рестораны, Гостиницы, Развлечения, Музеи, Транспорт, «Магазины ▾» последними — `CATEGORIES`): точки берутся прямо из векторных тайлов OpenFreeMap (source-layer `poi`, фильтр по `subclass` = исходный тег OSM), поэтому появляются сразу, с zoom ≥ 12. Отдельный источник `te-poi` добавляется в каждый стиль на `style.load` (у CARTO тайлы без subclass). Места рисуются флажками-булавками цвета категории (`pinImage`, картинки создаются заново после смены стиля). Надпись «Приблизьте карту» — ниже zoom 12 и при пустом результате ниже 14; «не найдено» — только с zoom 14, где в тайлах есть все места. Включённый чип — негативом (светло-серый фон #9aa0a6, белый текст; прежний #5f6368 Грегори попросил сделать вдвое светлее). У «Магазинов» чип из двух частей: название включает/выключает последний выбранный профиль, стрелка открывает меню профилей (продукты, рынки, промтовары, одежда, электроника, аптеки, ТЦ, сувениры, алкоголь). Подробности по клику (часы, сайт, телефон, кухня) — один запрос к OSM API: id точки в тайлах = osm_id·10 + тип (1 node, 2 way, 3 relation). Раньше был Overpass API — убран: 10–15 с на каждый сдвиг и частые 504.
- **Верхняя панель белая** (как кнопки MapLibre), значок гостиниц — монохромный SVG (цветной эмодзи кровати Грегори не понравился). **Звёздный фон** — холст `#stars` под прозрачным холстом MapLibre: 12 000 звёзд на небесной сфере, проецируются камерой с теми же центром, поворотом и наклоном, что у карты (`drawStars`), поэтому небо вращается вместе с глобусом как одно целое, как в globe.gl (плоский сдвигающийся фон Грегори отверг). **Наклон и поворот** доступны, только когда 100 px шкалы ≤ 100 км (`TILT_MAX_METERS_PER_100PX`); при отдалении карта сама выпрямляется. **Минимальный размер глобуса** (`minGlobeZoom`): на компьютере не мельче шкалы 500 км (радиус шара 660 px), на узком экране — не шире 1,1 ширины экрана. Минимальный зум зависит от широты центра (MapLibre рисует шар радиусом worldSize/2π/cos(lat)), поэтому пересчитывается после каждого движения. Строка источников по умолчанию свёрнута в кнопку ⓘ (удалять её нельзя — требование лицензий OSM, CARTO, Esri). Выравнивание (`settleGlobe`) — 2,4 с с затуханием. **Важно:** нельзя вызывать `easeTo` прямо из обработчика `moveend` — он приходит изнутри кадра анимации MapLibre, и новая анимация ломает внутреннюю очередь (`Attempting to run(), but is already running`, `_onEaseFrame is not a function`): отрисовка останавливается навсегда, глобус «виснет». Поэтому выравнивание и доводка до минимального размера запускаются через `setTimeout` и только если `!map.isMoving()` — заодно оно не перебивает перетаскивание. Звёзды вдвое крупнее, разных цветов, мерцают (`animateStars`, ~30 кадров/с, при движении карты — каждый кадр). Попап места закрывается при смене/выключении фильтра (`poiPopup`). **Шкала масштаба** — `RuScaleControl` справа внизу: до километра в «м», дальше в «км». Панель выбора карт тоже белая.
- **Внизу справа** — кнопки масштаба и шестерёнка (свой `SettingsControl` MapLibre) над строкой атрибуции. Шестерёнка открывает окно «О программе» с PWA-кнопкой «Установить на рабочий стол» — перенесено из photo-editor.
- Важно: `map.setStyle(..., { diff: false })` — без этого при смене провайдера MapLibre подставляет чужие шрифты (404 на глифы). После каждой загрузки стиля (`style.load`) заново ставятся globe, язык подписей и слой мест.

Иконки в `icons/` — временно взяты из travel-globe, своего логотипа ещё нет.

**Пляжи (2026-09-30):** слой «Пляжи» в «Слоях» (`id: "beaches"`): `natural=beach`, `leisure=beach_resort` — наклонный зонтик на песке, ярко-жёлтый `BRIGHT_YELLOW` #ffd600, как и кайтер (прямой зонтик, потом оранжевый Грегори попросил заменить), значок в центре объекта. В тайлах OpenFreeMap пляжей с названиями нет, поэтому всё из QLever (`BEACH_SPARQL`, своя очередь `beachQueue`, кэш `beachCells`/`beachFeatures`, GeoJSON `ov-beaches`), со шкалы 10 км (`BEACH_MAX_METERS_PER_100PX = 20000`, `beachMinZoom`; 3 км Грегори показалось мало). Кадр на «10 км» — пара градусов, поэтому квадраты `BEACH_CELL` = 2° (QLever отвечает за то же время) до 1,5° от центра — `loadQleverCell`/`qleverCells` принимают размер квадрата и охват. Подсказка при наведении — та же, что у значков троп (`HOVER_POI_LAYERS`), плюс покрытие и спасатели (`beachFacts`). Запрос к QLever общий: `qleverQuery` / `loadQleverCell` / `qleverCells` (квадраты `TRAIL_POI_CELL`), значки рисует один `trailPoiImage` (без белой обводки — с ней выглядели размытыми, Грегори 2026-09-30). На кнопках «Пляжи» и «Сёрфинг» — те же значки, что на карте (`glyphSvg`), а не эмодзи.

**Сёрфинг (2026-09-30):** отдельный слой «Сёрфинг» (`id: "surf"`, просьба Грегори — «отдельная закладка с неограниченной видимостью по всему миру»): `sport=surfing|kitesurfing|windsurfing` (`SURF_KINDS`) — ярко-жёлтый кайтер (змей, стропы, райдер на доске; доску над волной Грегори попросил заменить), на любом масштабе, от глобуса до улиц. В OSM их ~1900 на весь мир, QLever отдаёт все одним запросом за 1–2 с (`loadSurf`, один раз при включении; при ошибке повтор через 60 с). Плюс кайт-споты Эстонии из списка Грегори в Google Картах «Kite spots Estoni» (https://maps.app.goo.gl/yF56KrvH689bmRLr9) — 28 точек в `surf-spots.json` (name, note, lon, lat; безымянные «координаты» заменены заметкой). Список вытащен разово через `https://www.google.com/maps/preview/entitylist/getlist?...&pb=!1m4!1s<id списка>!2e1!3m1!1e1!2e2!3e2!4i500!16b1` (ответ начинается с `)]}'`; id — из ссылки после `!2s`); если Грегори дополнит список — выгрузить заново. Точка OSM ближе 300 м к точке списка не рисуется (`surfData`); точки списка — `osm: "list/N"`, подсказка берёт название и заметку из самой точки, без OSM API. Значки прореживаются при тесноте (`symbol-sort-key`: список первым), на глобусе видно ~90, в кадре Эстонии — все свои.

**Фото (2026-09-30):** план Грегори — три источника фото, каждый отдельным слоем, друг другу не мешают: (1) общедоступные фото Wikimedia Commons — сделано; (2) Mapillary — сделано (см. ниже); (3) личные фото — берутся с компьютера из папки, путь к альбому указывается в настройках **этой машины**; на телефоне — только общедоступные. Приложение рассчитано и на стороннего пользователя: всё личное (история поиска, настройки, путь к фото) хранится только на том устройстве, где задано (localStorage), и никуда не отправляется. Google Maps фото не берём: по лицензии их можно показывать только на картах Google, API платный и с ключом.
Слой «Фото» (`id: "photos"`, значок-фотоаппарат): со шкалы 3 км — розовые точки `PHOTO_COLOR` там, где есть снимки (`ov-photo-dots`, `PHOTO_DOT_MAX_METERS_PER_100PX = 5000`, `photoDotZoom`; точка ставится сразу после списка, до загрузки снимка), со шкалы 1 км — миниатюры 44 px (`ov-photos`, фильтр `has img`, `PHOTO_MAX_METERS_PER_100PX = 2000`, `photoMinZoom`) в тонкой белой рамке 1,5 px без серой каймы (толстая рамка Грегори не понравилась; `photoThumb` рисует на OffscreenCanvas квадрат из середины снимка, `addImage` с pixelRatio 2, размер 1 на всех зумах — ужатая картинка расплывается; кэш `photoImages` — после смены карты картинки ставятся заново). **Лента внизу** (`photoStrip`, `updatePhotoStrip` на moveend и после каждого квадрата): загруженные снимки в кадре слева направо, как на карте; ушедшие из кадра убираются; элементы переиспользуются (прокрутка не сбрасывается), колесо крутит ленту вбок. Снимки 72 px, рамка ленты 2 px, как у плитки карт; в уровень и в высоту плитки переключателя карт (76 px, снизу 24 px), от неё до правого края; кнопки справа внизу (шкала, ⓘ, шестерёнка, масштаб, геолокация) — поверх ленты (Грегори): лента лежит внутри контейнера карты с z-index 1, под углами MapLibre (z-index 2), а в конце ленты запас 150 px, чтобы последние снимки выезжали из-под кнопок. `body.has-photo-strip` поднимает `.map-status`. Щелчок по снимку в ленте — `selectPhoto`: тот же снимок на карте крупнее (×1,4) в розовой рамке поверх всех (`ov-photo-selected`, картинка `photo-selected`), в ленте розовая рамка, открывается подсказка; снимается на `movestart`. Наведение на миниатюру на карте подсвечивает её в ленте и прокручивает к ней. **Щелчок по снимку на карте и в ленте работает одинаково** (`selectPhoto`; жалоба Грегори: после щелчка мимо окно уходило, а выделение оставалось): выделение живёт, пока открыто окно снимка — закрылось окно (щелчок мимо, сдвиг карты, другой снимок) → снимается и выделение (`close` у попапа); уход курсора окно выделенного снимка не прячет. Окно снимка — `closeOnClick: false`: на телефоне касание сначала даёт mousemove (окно открылось), и click того же касания сразу его закрывал («на телефоне на фотку не кликнуть»); щелчок мимо снимка закрывает его свой обработчик `map.on("click")`. **Галерея** (только на компьютере, `pointer: fine`): двойной щелчок по снимку на карте, в ленте или в окне снимка — `openPhotoGallery`, отдельное окно `gallery.html` (одно и то же, имя "travel-earth-gallery") со всеми снимками ленты, начиная с выбранного; карта при этом не приближается (`evt.preventDefault()` в не-делегированном `dblclick`). Список — через localStorage `travel-earth.gallery`. В галерее: крупный снимок (миниатюра Commons 1920 px или оригинал, если он меньше; пока грузится — размытая миниатюра), подпись, автор · дата · лицензия, ссылка на Commons, счётчик, стрелки, лента миниатюр, ← → Home End, Esc закрывает окно. **Галерея ведёт карту** (Грегори: «фокус на карте при просмотре фото»): при каждом снимке галерея шлёт `postMessage` в главное окно (`window.opener`), там снимок выделяется на карте и в ленте без окна (`selectPhoto(f, { popup: false })`, `galleryFocus`), а если он у края или за кадром — `easeTo` к нему; выделение не снимается на `movestart` от самой галереи (нет `originalEvent`), только от руки; на `pagehide` галерея шлёт `closed` — выделение снимается. **Телефон** (ширина ≤ 600 px): окно снимка у точки уходило за край — там оно карточкой над лентой во всю ширину (`className: "photo-sheet"`, CSS с `!important` перебивает transform, который MapLibre пишет каждый кадр; элемент переносится в `body`, потому что `#map` с `position: fixed` — свой слой наложения, и внутри него карточку накрывали «Слои» и кнопки). Касание пальцем тоже присылает mousemove — подсказки по нему не открываются (`touchPointer` по `pointerType`), только по click: иначе окно появлялось под пальцем и забирало click того же касания. Commons API (CORS `origin=*`, миниатюры с `access-control-allow-origin: *`): `list=geosearch` ищет только в прямоугольнике до ~0,15° (иначе `toobig`) и отдаёт до 500 ближайших к его центру — поэтому квадраты тайлов не крупнее 12-го уровня (0,09°), на квадрат два запроса: список до 500 точек, из него по одному jpg/webp на клетку сетки `PHOTO_GRID` 4×4 (ближайший к центру клетки — иначе снимки с одной точки слипаются в один значок), потом `prop=imageinfo` по их pageids (миниатюра 120 px, автор, лицензия, описание, дата из extmetadata). Квадрат, где 500 точек (старые центры городов — там они покрывают лишь пятачок), попадает в `photoDense` и делится на четыре, пока четвертинки не мельче половины тайла экрана. Очередь `photoQueue` в 3 потока, ближние к центру квадраты первыми, не больше 40 за раз; не дошедшие при сдвиге карты забываются. Подсказка при наведении — через общий `trailPoiPopup` (`showPhotoInfo`): снимок 330 px с заранее заданным размером (окно не прыгает), подпись, автор · дата · лицензия (Commons требует указывать), ссылка на страницу снимка. Слой ниже всех своих значков (`TRAIL_POI_ORDER`). Проверено: Таллин на «3 км» — ~155 точек и ~145 снимков в ленте; центр Таллина на «100 м» — 64 миниатюры, на «500 м» — 64, Пениши (Португалия) — 29.

**Снимки улиц — Mapillary (2026-09-30, пункт 2 плана фото):** слой «Снимки улиц» (`id: "mapillary"`, значок — уличная камера видеонаблюдения на кронштейне (Грегори выбрал по картинке; человечек Material "streetview" не подошёл)). Ключ — Client Token приложения Грегори «Travel Earth» (`MAPILLARY_TOKEN`, App ID 27764742799866922; токен открытый — лежит в коде, даёт только чтение общедоступного; Client Secret не нужен и не хранится). Векторные тайлы `tiles.mapillary.com/maps/vtp/mly1_public/2/{z}/{x}/{y}` (CORS *): слой `sequence` (линии съёмки, есть на всех зумах) и `image` (точки снимков, только в тайлах 14-го уровня). Тайлы очень тяжёлые (центр Таллина: z13 ~1 МБ, z14 ~2,6 МБ, z10 ~5 МБ, z6 ~10 МБ), поэтому два источника с одним зумом каждый, и MapLibre грузит источник, только когда виден его слой: `ov-mapillary` — только z13 (линии `ov-mly-lines` со шкалы ~1 км, дальше растягиваются), `ov-mapillary-vec` — только z14 (точки `ov-mly-images` с зума 16, ~100 м). Зелёный Mapillary `MLY_COLOR`, линии тонкие и полупрозрачные (толстые сливались в сплошную зелень). Наведение (на телефоне — касание) на линию или точку — то же окно, что у Commons (`showMapillaryInfo` → `showPhotoInfo`; у линии — её снимок-представитель `image_id`, окно у курсора): снимок 1024 px, «Снимок улицы»/«Панорама 360°», автор, дата, CC BY-SA 4.0, ссылка на mapillary.com; данные — Graph API `graph.mapillary.com/{id}?fields=…`, кэш `mlyInfo`. Двойной щелчок по точке, линии или снимку в окне (на компьютере) — отдельное окно `viewer.html` (MapillaryJS 4.1.2 с unpkg, одно окно "travel-earth-mapillary"): переход по снимкам стрелками, в панорамах — вращение; оно шлёт `postMessage` с положением камеры и направлением взгляда → на карте розовая точка с веером взгляда (`ov-mly-pos`, `mlyPosImage`, поворот по bearing), карта подвигается за камерой, если точка у края; при закрытии точка убирается.

## Правила для всего нового (Грегори, 2026-09-30)

- **Наши значки — всегда сверху.** Любой свой слой значков ставится выше подложки, её подписей и линий/табличек троп, а внутри своих — важные выше менее важных (сейчас: вышки, смотровые площадки, маяки, пикник над указателями, щитами, водой, кострищами, палатками). Верхний слой MapLibre и расставляет первым, так что при тесноте уступают нижние. Порядок держать при любом добавлении слоёв: включение другого вида троп, смена карты (`setStyle`) — сейчас это `raiseTrailPoi` / `TRAIL_POI_ORDER` (значки троп, пляжей и сёрфинга); новый слой — вписать туда же, а не ставить `before` наугад.
- **Окна на карте** — скруглённые (10px), закрываются сразу на `movestart` (сдвиг или зум); новое окно добавить в список в обработчике `movestart`. Подсказка при наведении не прячется, пока курсор на ней.
- **Значки на кнопках** — монохромные условные обозначения, как на картах (`currentColor`: у включённого чипа белеют вместе с текстом), а не цветные эмодзи («не как конфетки»): у слоёв — `CHIP_ICONS` (горы, вершина в горизонталях, блок-диаграмма, босые следы, велосипед Material pedal_bike, велосипед под вершинами, поезд как у флажков станций); исключение — «Пляжи» и «Сёрфинг», на них жёлтые значки с карты (`glyphSvg`). У «Мест» — Material Icons через `placeIcon` (2026-09-30, Грегори: «Рестораны вообще не понятно что» — 🍴 в шрифте Windows не узнать): нож и вилка, кровать (`HOTEL_ICON`), билет со звездой (Развлечения, было 📷), колонны (Музеи), автобус (`PIN_GLYPHS.bus`), тележка (Магазины).
- **Курсор** над всем, о чём щелчок или наведение что-то покажет, — стрелка, над пустой картой — ладонь; новый кликабельный слой — добавить в проверку курсора (`ownInfoLayers` / `mapInfoHit`).

## Локальный запуск для тестов

- `start.bat` — поднимает `python -m http.server 8643` в отдельном свёрнутом окне «Travel Earth server» (если порт ещё не занят) и открывает `http://localhost:8643/` окном-приложением Chrome (`Profile 1`) или Edge. Порт 8643 выбран, чтобы не пересекаться с photo-editor (8642).
- `install_desktop_shortcut.vbs` — разовый установщик: создаёт на рабочем столе ярлык «Travel Earth», указывающий на локальный `start.bat` этой папки (а не на GitHub Pages). Файл сохранён в UTF-16 LE с BOM — иначе Windows Script Host читает кириллицу в сообщениях как ANSI и показывает кракозябры.
- **Спутник на большом приближении:** тайлы Esri запрашиваются с `?blankTile=false` — где подробного снимка нет, сервер отдаёт 404 (без CORS-заголовков, в консоли это «Failed to fetch») вместо картинки-заглушки «Map data not yet available», и MapLibre растягивает последний настоящий снимок. Ошибки в консоли безвредны.
- **Низ экрана без подложек (2026-09-27, просьба Грегори):** подсказки `#map-status` — внизу по центру над строкой шкалы, белым текстом с тёмной обводкой (читается и на карте, и на звёздах); шкала так же прозрачная; ⓘ крупнее (32 px), без подложки, белый фон только у раскрытой строки источников. Попап места открывается один раз, уже с подробностями из OSM API (ожидание до 1,5 с): раньше он показывался с «Загрузка…», потом менял размер и прыгал.
- **Заголовок окна:** theme-color светло-серый (#f1f3f4, как кнопки при наведении) — Chrome красит им заголовок окна; прозрачным его в окне `chrome --app` сделать нельзя. Чёрный пробовали — Грегори попросил светло-серый под цвет карты. У установленного приложения (кнопка в About) — `display_override: window-controls-overlay`: заголовок прозрачный, `.titlebar-drag` — полоска для перетаскивания окна, `.top-bar` опускается под неё (`env(titlebar-area-*)`). Попап места закрывается, когда его флажок пропадает с карты (отдаление ниже POI_MIN_ZOOM или проверка на `idle`).
- **Аэропорты и транспорт (2026-09-27):** аэропорты — в отдельном слое тайлов `aerodrome_label` (в `poi` их нет), свой слой карты `poi-air`, классы international/public/regional. Видны, когда шкала показывает 5 км и меньше (`AIRPORT_MAX_METERS_PER_100PX` = 10000, 2026-09-29 поднято с 3 км по просьбе Грегори: шкала берёт круглое число ≤100 px) — порог по широте, `setLayerZoomRange` на moveend. Аэропорты только внутри «Транспорта» (`airports: true`; отдельный чип Грегори попросил убрать). Транспорт: вокзалы, ж/д станции, метро (subclass `subway`), станции канатных дорог (class `aerialway`, subclass `station`), паромы, аэропорты — слой `poi`; остановки автобусов и трамваев — отдельный слой `poi-stops`, только когда шкала ≤ 100 м (`STOP_MAX_METERS_PER_100PX` = 200; 200 м Грегори счёл слишком мелко). Каждый вид транспорта своего цвета со своим белым значком (`modes`: метро красное «M», трамвай оранжевый, автобус зелёный, канатка фиолетовая, паром голубой, поезд синий; аэропорт серо-синий; фуникулёр ядовито-зелёный #39ff14 с чёрным значком и обводкой — `ink` в `pinImage`, Грегори: «их всегда так тяжело найти»; рельсы того же цвета; виден с «1 км», как метро). Канатные дороги (2026-09-27): тот же ядовито-зелёный с чёрным значком (Грегори: «тоже подними и сделай зелёными»; обычный зелёный занят автобусами). Их станции в тайлах только с z14, а тросы (transportation, subclass cable_car/gondola/mixed_lift) — с z12; поэтому по id троса OSM API `way/{id}/full.json` отдаёт узлы `aerialway=station` (вместе с промежуточными) → GeoJSON-источник `te-cable`, слой `poi-cable` до z14, дальше — станции из тайлов. Рельсы и тросы — слой `poi-lift-line`; флаг категории `lifts`. Станции фуникулёров в тайлах не отличить от ж/д (railway station/halt), зато рельсы помечены (`transportation`, subclass `funicular`): `updateFunicularStations` на idle считает станцией фуникулёра ж/д станцию ближе 50 м к таким рельсам и переносит её в слой `poi-funicular` (фильтр по id); рельсы подкрашены (`poi-funicular-line`). Но рельсы есть в тайлах только с zoom 14, а станции с 12 — поэтому ещё `checkFunicularTags`: теги всех новых railway station/halt в кадре одним пакетным запросом к OSM API (`nodes.json?nodes=…`), фуникулёр = `station=funicular` или `funicular=yes`, ответ кэшируется в `funicularTags`. Так фуникулёр виден с того же масштаба, что метро и поезда (просьба Грегори). Проверено на Киеве и Монжуике (Барселона). Флажки крупнее (icon-size 1→1.4). `PIN_GLYPHS` — контуры Material/MDI через Path2D, `text:` — буква, `{path, rotate}` — наклонённый значок. Id в `aerodrome_label` кодируется так же, как в `poi`, — OSM API отдаёт подробности. `poiZoomRange` даёт по категории зум появления и зум, с которого можно писать «не найдено».
- **История поиска (2026-09-29):** до 20 выбранных результатов в localStorage (`travel-earth-search-history`), показывается при пустой строке поиска (фокус, стирание, ✕), клик ведёт на место без нового запроса к Nominatim, «Очистить историю» внизу. Вместо значка часов у строки ручка перетаскивания (`.search-drag`, pointer events) и крестик «удалить» — Грегори выстраивает из истории список избранного, поэтому повторный поиск известного места не поднимает его наверх.
- **Слои поверх карты (2026-09-28):** кнопка «Слои» над переключателем карт, галочки, можно несколько сразу, запоминаются в localStorage `travel-earth.overlays`, заново добавляются в style.load (`applyOverlays`). Грегори: «карты и слои — разные вещи, даже в Google Maps так нет». Рельеф (hillshade) и 3D-рельеф (`setTerrain`, работает и на глобусе) — AWS Terrain Tiles terrarium, у каждого свой raster-dem источник (MapLibre предупреждает про общий). Горизонтали с подписями «N м» — maplibre-contour 0.1.1 с unpkg (`mlcontour.DemSource`, строит линии в браузере; шрифт подписей берётся из первого symbol-слоя текущего стиля — у CARTO свой сервер шрифтов). Пешие тропы / велодорожки / маунтинбайк — растровые прозрачные тайлы Waymarked Trails (CORS *). Железные дороги — свои линии из `transportation` (class rail/transit), цвет по subclass как у флажков станций, тоннели пунктиром: тайлы OpenRailwayMap отдают 403 чужим сайтам даже с Referer. Все слои встают перед первым symbol-слоем основы (под подписи и флажки). Проверено на Монсеррате (рельеф+горизонтали+тропы, 3D на спутнике) и на телефоне.
- **Правки 2026-09-29:** «Слои» — столбик чипов по образцу «Места» (открыт, пока снова не нажать кнопку; без закрытия щелчком мимо). Тропы (пешие/вело/МТБ) только с зума 9 (`TRAILS_MIN_ZOOM`) — на глобусе были толстые размытые полосы; вблизи линии тоже были широкими и мутными (растянутые 256-е тайлы), поэтому источник `tileSize: 128`, maxzoom 18 — тайлы на уровень детальнее, линии вдвое тоньше (номерки маршрутов тоже вдвое мельче). Масштаб появления троп Грегори просил больше не трогать. Вблизи (с `TRAILS_VECTOR_ZOOM` 11, шкала ~2 км; было 14, потом 12 — на ужатых картинках таблички номеров превращались в пустые квадратики и слипшиеся овалы, а на юге шкала «1 км» — это ещё зум 11,5) вместо картинок — свои линии: Грегори хотел тонкую линию, но растущий с приближением номер, а в картинке они неразделимы. Маршруты — из API Waymarked Trails (тот же поддомен hiking/cycling/mtb, что у картинок, CORS *): квадратами 0,1°, до 40 ближайших к центру (на большом экране при зуме 11 в кадре ~32; прежний предел 16 оставлял края пустыми), в 3 параллельные очереди (`trailQueues`); на квадрат два запроса — `list/by_area?bbox=…` (список маршрутов: ref, name, group) и `list/segments?bbox=…&relations=…` (линии, уже обрезанные по квадрату); bbox и координаты в метрах EPSG:3857 (`toMercator`/`fromMercator`), ~0,2–0,5 с на квадрат. Кэш `trailCells`/`trailFeatures`. Цвет по `group` (INT красный, NAT синий, REG оранжевый, LOC фиолетовый — как у Waymarked). Номер = ref или name не длиннее 16 знаков — на табличке (`plateImage`: плашка цвета маршрута без каймы (кайму Грегори попросил убрать), растягивается `icon-text-fit`), всегда горизонтальной: текст вдоль петляющих горных троп MapLibre почти не ставил. Раньше данные брались из Overpass — убран 2026-09-29: 1–4 с на квадрат, постоянные 429/504 на всех зеркалах, тропы появлялись кусками (жалоба Грегори «не всё прогружает»). Значки у троп (указатели и щиты «i», пикник, кемпинги, вода — `TRAIL_POI_CLASSES`) — общий для всех видов троп слой `ov-trail-poi` из `te-poi` с зума 14 (`TRAIL_POI_ZOOM`; в основе карты они только с 15–17 по рангу, Грегори: «появляются в последний момент»). Мельче 14 в тайлах OpenFreeMap этих точек нет (Waymarked указателей не отдаёт), поэтому со шкалы 3 км они подгружаются из QLever (`loadTrailPoiCell`, SPARQL `TRAIL_POI_QUERY` к https://qlever.dev/api/osm-planet, центроиды через `geof:centroid`: tourism information/viewpoint/picnic_site/camp_site, amenity drinking_water, смотровые вышки, кострища; туалеты и достопримечательности — только из тайлов, в городах их слишком много) квадратами по полградуса (`TRAIL_POI_CELL`: QLever отвечает 8–17 с почти независимо от размера), одной очередью после троп, в GeoJSON-слой `ov-trail-poi-far` (до зума 14). Overpass, который был раньше, 2026-09-30 перестал отвечать совсем (overpass-api.de — таймаут соединения, mail.ru — 10–40 с) — заменён на QLever; при ошибке повтор через 60 с. Грегори согласен: «если топтаться на месте, появятся; не успеют — не очень надо». Ошибки молча, повтор сам через 60 с. Значки свои, в одном стиле (`TRAIL_POI_ICONS`, `trailPoiImage`): символ цвета группы без кружка и без обводки (белую обводку убрали 2026-09-30 — размыто), 24 px (Грегори: «без кружков и в два раза крупнее») — светло-синие указатель/«i» (синего было слишком много), серые щит/карта (их много), зелёные смотровая площадка («красивый вид» — точка с веером лучей; бинокль, значок вышки и горы с солнцем Грегори отверг), вышка, достопримечательность; чёрно-белый маяк (поле `white` — белые детали поверх); светло-зелёная палатка, коричневый пикник, красное кострище, голубые вода/WC. Навесов (shelter) нет: почти все — остановки автобуса (Грегори: «навесы убирай»). Вид точки из тайла — `TRAIL_POI_KIND` (class + subclass: information → guidepost/board/map/info, attraction → viewpoint), из QLever — по `?kind` и `?info`; метки краской (route_marker) не показываются. При наведении (на телефоне — по касанию) подсказка `showTrailPoiInfo` без крестика: вид, название, высота, описание, направления указателя; теги (кэш `trailPoiTags`) у всех точек берутся из OSM API (не дольше 1 с). Общий щелчок по карте на этих значках не срабатывает. Смотровых вышек (`man_made=tower` + `tower:type=observation`), кострищ (`leisure=firepit`) и маяков (`man_made=lighthouse`; в тайлах маяк — обычная attraction и только с 14) в тайлах нет, поэтому QLever грузится на любом зуме, и с 14 они видны отдельным слоем `ov-trail-poi-extra`. Видимость: со шкалы 3 км — только вышки, смотровые площадки, маяки и пикник (`TRAIL_POI_FAR_KINDS`, `TRAIL_POI_MAX_METERS_PER_100PX = 5000`, `trailPoiMinZoom`); остальное — со шкалы 500 м (`TRAIL_POI_NEAR_MAX_METERS_PER_100PX = 1000`, `trailPoiNearZoom`; Грегори: 3 км для всех — слишком густо, 100 м — слишком поздно, «давай на 500 м»). Пороги по широте, пересчёт в `updateScaleZooms`. Дальние виды рисуются с `icon-allow-overlap` (флаг `always`), чтобы не пропадали за табличками троп. Теги для подсказки у точек QLever — из OSM API по "node/123" (`loadOsmTags`). Подсказка не прячется, пока курсор на ней (в ней ссылка на сайт; жалоба Грегори «невозможно навести мышку»): уход со значка прячет её через 300 мс (`hideTrailPoiInfoSoon`), и только если курсор не над ней (`:hover`). Все окна на карте (`poiPopup`, `mapPopup`, `trailPoiPopup`, попап маркера поиска) закрываются на `movestart` — как только карта начала двигаться или приближаться (Грегори, 2026-09-30); углы попапов скруглены (10px). Порядок слоёв (`raiseTrailPoi`, после каждого `addTrailLines`): значки у троп — над линиями и табличками всех видов троп и над подписями карты (но под флажками мест `POI_LAYERS`), дальние виды — самые верхние (`TRAIL_POI_ORDER`); верхний слой расставляется первым, так что при тесноте уступают нижние (Грегори: «наши приоритеты должны быть сверху» — раньше палатка перекрывала маяк, таблички троп — значки). Курсор над всем, о чём щелчок/наведение что-то покажет (наши значки и флажки, подписи карты из `mapInfoHit`), — стрелка вместо ладони; проверка раз за кадр, при нажатой кнопке не трогается.de бывает недоступен по 20+ с на запрос, и значки ждали его на каждом квадрате. Слои: тайлы `ov-trail-poi` (дальние виды) и `ov-trail-poi-near` (остальные) с 14; GeoJSON из QLever `ov-trail-poi-far` и `ov-trail-poi-near-far` до 14, `ov-trail-poi-extra` (вышки, маяки) и `ov-trail-poi-extra-near` (кострища) — на любом зуме; список — `TRAIL_POI_LAYERS`. `updateTrails` грузит точки и мельче `TRAILS_VECTOR_ZOOM`. Маяки грузятся только вместе со слоем троп. При ошибке квадрат повторяется сам через 30 с (`setTimeout(updateTrails)`), не дожидаясь сдвига карты. Данные передаются карте повторно на idle (`trailDirty`): раз наблюдалось, что setData терялся и тайлы оставались пустыми. Порядок карт: Пастельная после Светлой; карта по умолчанию (`DEFAULT_BASEMAP`) — Яркая (liberty), просьба Грегори. Кнопка геолокации внизу справа (как Google Maps/Mapy.com): пустой центр — выкл., синий — карта следует за мной, серый — слежу, но карту сдвинули рукой (`dragstart`); статус в localStorage `travel-earth.geolocate`, при «on» при запуске карта встаёт на меня. Щелчок по карте: по подписи/значку — попап с описанием из Википедии (через Викиданные; у CARTO id не OSM, поэтому поиск OSM-объекта через Nominatim по имени рядом с точкой), значки подложки без названия (пикник, навес, туалет и т.п.) — тоже, если вид известен (`poiKindName`: `POI_KIND_NAMES`, `TRAIL_POI_KIND_NAMES`, `MAP_POI_KIND_NAMES`; жалоба Грегори «мышка не реагирует на значки»), заголовок — вид; мимо значков — GPS-координаты (щелчок копирует) и адрес Nominatim reverse; по звёздам — ничего (`isPointOnMapSurface`).
